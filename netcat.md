- # Работа с сетевыми соединениями
   
> Netcat (часто вызывается как nc) — это консольная утилита для чтения и записи данных через TCP и UDP. Позволяет быстро проверять порты, устанавливать соединения, передавать данные, слушать входящие подключения и отлаживать сетевые сервисы.

**<span style="color: green">nc</span>** — основная команда утилиты в Linux и во многих Unix-подобных системах.

**<span style="color: green">netcat</span>** — альтернативное имя команды в некоторых системах.

**<span style="color: green">ncat</span>** — современная реализация netcat из набора Nmap, часто встречается в Windows и Linux.

❗❗❗ В разных системах используются разные реализации netcat, поэтому набор ключей может немного отличаться: **<span style="color: green">traditional</span>**,  **<span style="color: green">OpenBSD nc</span>**,  **<span style="color: green">Ncat</span>**. 

Смотреть справку: **<span style="color: green">nc -h</span>** или **<span style="color: green">ncat –help</span>**

# Установка в Linux и Windows

**<span style="color: green">sudo apt install netcat-openbsd</span>** — установка в Debian/Ubuntu.

**<span style="color: green">sudo apt install netcat-traditional</span>** — установка классической версии в Debian/Ubuntu.

**<span style="color: green">winget install Nmap.Nmap</span>** — установка Ncat в Windows через winget.

**<span style="color: green">choco install nmap</span>** — установка через Chocolatey в Windows.
    
> В Windows классический netcat встречается реже. Чаще используется именно **<span style="color: green">ncat.exe</span>** из пакета Nmap.

# Основные опции

|   Опция    |                                                           Описание        |
| :--------: | :------------------------------------------------------------------------ |
|     -l     | Режим прослушивания (listener), ожидание входящих соединений              |
|     -v     | Подробный вывод (verbose), показывает детали соединения                   |
|     -z     | Режим сканирования, без отправки данных, только проверка открытости порта |
|     -u     | Использование UDP вместо TCP по умолчанию                                 |
|     -n     | Отключение DNS-разрешения, работа только с IP-адресами                    |
|    -w N    | Таймаут соединения в N секунд                                             |
|     -N     | Закрытие соединения при достижении EOF                                    |
|     -k     | Продолжение прослушивания после отключения клиента (keep listening)       |
|  -p порт   | Указание порта источника (для клиента)                                    |
|     -4     | Использование только IPv4                                                 |
|     -6     | Использование только IPv6                                                 |
| -e команда | Выполнение команды при соединении (только GNU netcat)                     |

# Проверка доступности порта

#### Проверка HTTP-порта:

```bash
nc -zv scanme.nmap.org 80
```

#### Проверка открытости TCP-порта без передачи данных:

```bash
nc -vz 192.168.1.1 22
```

#### Проверка диапазона портов с фильтрацией открытых:

```bash
nc -vz 192.168.1.1 20-80 2>&1 | grep succeeded
```

**2>&1** перенаправляет **stderr** в **stdout**, так как nc выводит результаты в stderr.
Это удобно для быстрой ручной проверки, но для полноценного сканирования сети обычно используют специализированные инструменты вроде Nmap.

#### Проверка UDP-порта:

```bash
nc -vzu 192.168.1.1 53
```

#### Проверка с таймаутом для скриптов:

```bash
nc -vz -w 3 192.168.1.1 3306
echo $?                    # 0 — доступен, 1 — нет
```

❗❗❗ **Если порт закрыт или фильтруется файрволом, поведение может отличаться: вы можете получить явную ошибку, таймаут или отсутствие ответа.**

# Получение баннера сервиса

Быстрое определение версии службы путём чтения приветственного сообщения:

```bash
echo "" | nc -w 3 192.168.1.1 22
```
	Результат: SSH-2.0-OpenSSH_8.9p1.

# HTTP-запрос вручную:

```bash
printf "HEAD / HTTP/1.0\\r\\nHost: example.com\\r\\n\\r\\n" | nc -w 3 example.com 80
```

# Подключение к TCP-сервису вручную

Открывает TCP-соединение с указанным хостом и портом:

```bash
nc example.com 80
```

После подключения можно вручную отправить HTTP-запрос:

```text
GET / HTTP/1.1
Host: example.com
```

> Такой способ полезен для отладки HTTP, SMTP, POP3, IMAP и других текстовых протоколов.

# Запуск TCP-сервера в режиме прослушивания

Запускает простой TCP-слушатель на порту 9000:

```bash
nc -lv 9000
```

На другой машине или в другом терминале можно подключиться:

```bash
nc 127.0.0.1 9000
```

Все, что будет введено на одной стороне, появится на другой.

Создание простого слушающего сокета для тестирования:

```bash
nc -lvnp 8080
```

-l — слушать, -v — подробно, -n — без DNS, -p — указать порт явно.

После подключения клиента всё, что он отправляет, отображается в терминале, ввод в терминале отправляется клиенту (интерактивный чат).

Непрерывное прослушивание нескольких клиентов:

```bash
nc -lvnkp 8080
```

Без -k слушатель завершается после первого клиента.

# Передача сообщений между двумя машинами

> Один из самых простых сценариев использования netcat — организация мгновенного текстового обмена между двумя узлами.

На принимающей стороне:

```bash
 nc -lv 9000
```

На отправляющей стороне:

```bash
nc 192.168.1.20 9000
```

После этого можно печатать сообщения в терминале.

# Передача файла

На принимающей стороне:

```bash
nc -lv 9000 > received_file.txt
```

На отправляющей стороне:

```bash
nc 192.168.1.20 9000 < file.txt
```

> Все данные, пришедшие по соединению, будут записаны в файл.

**❗❗❗ Netcat не добавляет проверки целостности, шифрования и подтверждения доставки на прикладном уровне. Для важных файлов лучше дополнительно проверять хеш-суммы.**

# Передача каталога через tar и netcat

В Linux часто используют связку **<span style="color: green">tar</span>** и **<span style="color: green">nc</span>**.

На принимающей стороне:

```bash
nc -lv 9000 | tar -xvf -
```

На отправляющей стороне:

```bash
tar -cvf - mydir | nc 192.168.1.20 9000
```

> Каталог архивируется в поток и сразу передается по сети без промежуточного файла.

# Работа с UDP

**<span style="color: green">nc -u host port</span>** — отправка данных по UDP.

**<span style="color: green">nc -ul port</span>** — прослушивание UDP-порта.

На принимающей стороне:

```bash
nc -ul 9999
```

На отправляющей стороне:

```bash
nc -u 127.0.0.1 9999
```

**<span style="color: green">-u</span>** — использование UDP вместо TCP.

**❗❗❗ UDP не гарантирует доставку, порядок пакетов и отсутствие потерь, поэтому результаты тестов по UDP нужно интерпретировать осторожно.**

# Использование таймаута

**<span style="color: green">nc -w 3 host port</span>** — задает таймаут в секундах.

```bash
nc -zvw 3 example.com 443
```

**<span style="color: green">-w 3</span>** — ожидать не более 3 секунд.

> Это полезно в скриптах, чтобы команда не зависала слишком долго.

# Отправка строки в сервис

**<span style="color: green">echo ‘text’ | nc host port</span>** — отправка одной строки в удаленный сервис.

```bash
echo 'hello' | nc 127.0.0.1 9000
```

В Linux часто используют и вариант:

```bash
printf 'GET / HTTP/1.0\r\n\r\n' | nc example.com 80
```

# Проверка HTTP вручную

```bash
printf 'GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n' | nc example.com 80
```

> Это позволяет увидеть сырой HTTP-ответ сервера без браузера и без curl.

# Использование в простых пайплайнах

**<span style="color: green">command | nc host port</span>** — отправка вывода команды по сети.

**<span style="color: green">nc -lv port | command</span>** — передача входящих данных другой команде.

```bash
date | nc 127.0.0.1 9000
```

# Применение в диагностике

> Netcat особенно полезен системным администраторам, DevOps-инженерам и разработчикам для быстрой ручной проверки сетевой инфраструктуры.

Типичные задачи:

- проверка, открыт ли нужный порт
- проверка, принимает ли сервис соединения
- ручная отладка текстовых протоколов
- тестирование локальных и удаленных TCP/UDP-сервисов
- быстрая передача данных между машин

# CTF-соревнования
    
> В CTF (Capture The Flag) netcat является базовым инструментом для взаимодействия с удалёнными сервисами. Согласно статистике, около 73% заданий категории pwn/web требуют использования nc для подключения к серверам

# Базовое подключение к заданию

Стандартный формат задания: `nc <IP> <PORT>`. После подключения сервер может запросить ввод специальной команды для получения флага или выдать его сразу.

```bash
# Подключение к серверу CTF
nc -vn 192.168.1.100 9999
# Сохранение сессии для анализа
nc 10.0.0.2 8888 | tee session.log
```
